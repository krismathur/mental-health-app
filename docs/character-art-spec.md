# MindZone character art spec

The 10 characters in `public/js/roster.js` are fictional and must stay that way.
This document records the constraints any replacement art has to meet, because
the athlete studio does not simply draw the body PNG — it **analyses it pixel by
pixel** to decide where clothing goes.

## Current status

The art shipped today is **placeholder**, generated by
`scripts/generate-character-art.py`. It is original and legally clean, and it
satisfies every constraint below, but it reads as a flat mannequin rather than a
person. It exists so the app keeps working; it is not final.

## Files per character

| File | Size | Format |
|---|---|---|
| `public/images/characters/<id>.jpg` | 330×440 | JPG, opaque |
| `public/images/characters/bodies/body-<id>.png` | 640×1020 | PNG, **RGBA with transparent background** |

`<id>` must match the `id` field in `roster.js`. After replacing art, bump
`ART_VERSION` in `roster.js` so browsers drop the cached files.

## Why the body PNG is constrained

`public/js/athlete-studio.js` composites 52 photographic gear items onto the
body at runtime. To do that it runs these detectors over the pixels:

| Function | What it looks for | Requirement on the art |
|---|---|---|
| `isSkinPixel` (~line 241) | warm pixels: `r ≥ 45`, `r ≥ g-2`, `r-b ≥ 8`, chroma `≥ 10` | Exposed skin must be a warm tone, not grey or blue-cast |
| `isBodyPixel` (~254) | alpha `≥ 36`, and **not** (chroma `< 28` and luma `> 198`) | Background must be transparent; near-white areas read as "not body" |
| `isTankPixel` (~724) | chroma `< 48`, `40 < luma < 195`, not skin | Base top must be a **mid-grey, low-saturation** tank |
| `isBaseShorts` (~733) | luma `< 95`, chroma `< 42`, not skin | Base bottom must be **dark and desaturated** |
| `measureBody` (~266) | per-row horizontal runs of body pixels | Figure must be a single connected front-facing silhouette |
| `faceCenter` (~1092) | skin cluster in the upper region | Face must be visible skin, not fully covered by hair or shadow |

Get any of these wrong and gear will float, clip, or vanish — the failure is
silent, so **always test in the studio**, not by eyeballing the PNG.

## Pose and framing

Match the placeholders exactly or gear alignment drifts:

- Front-facing, standing, arms down and slightly away from the torso.
- Feet near the bottom edge; head near the top with a small margin.
- Neutral expression, no props, no ball, no team markings.
- Same camera distance for all 10 so they look like one set.

## Base layer

Every character wears the same base outfit, and only this:

- **Top:** plain mid-grey tank, roughly `#969696`. No logo, text, or number.
- **Bottom:** plain dark shorts, roughly `#262628`. No logo, text, or number.
- **Shoes:** plain white/off-white.

Anything else is added at runtime from `public/images/studio/gear/`.

## Skin tones

The six studio tones live in `SKINS` in `athlete-studio.js`. Each character has
a default `skin` in `roster.js`; the player can change it, and the studio
recolours the art. Draw the character in their default tone:

| Key | Hex |
|---|---|
| `fair` | `#f3d2c2` |
| `light` | `#e0ac86` |
| `tan` | `#c68642` |
| `brown` | `#8d5524` |
| `deep` | `#5c3317` |
| `rich` | `#3b2214` |

## Hard rules

1. **No real people.** Not a real athlete, not a celebrity, not a recognisable
   composite of one. The whole point of this work was removing them.
2. **No real league or team marks.** No NBA/NFL/MLB/MLS/ATP, no club crests, no
   real kit designs. League labels are ours: HOOPS, PITCH, DIAMOND, GRIDIRON,
   COURT.
3. **No licensed photography.** If the art is generated, keep the prompt and the
   tool on record. If it is commissioned, get the rights assigned in writing.
4. **Keep the set diverse** across skin tone, build, and gender — it currently
   runs 5 female / 5 male across 6 tones. Don't regress that.

## Regenerating the placeholders

```bash
python3 scripts/generate-character-art.py
```

Edit `CHARACTERS` / `BUILDS` in that script to change proportions. Verify with
the detector check described in "Testing" below.

## Testing a replacement

1. Drop the new files in, bump `ART_VERSION` in `roster.js`.
2. Open `avatar.html`, launch the studio, and for **each** character cycle
   through: a top, a bottom, a hat, shoes, and all six skin tones.
3. Watch for gear that floats off the shoulders, clips through the torso, or
   fails to appear — that means a detector is not matching.
4. Check the picker on `meditation.html` renders all 10 cards.
